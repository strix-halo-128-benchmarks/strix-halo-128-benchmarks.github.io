Leaderboards, by axis

Contents

    Every number here comes from the same matrix as the report, with the same rules. Ranked on one axis at a time, because there is no composite score and this project does not publish one — a model that wins code and loses knowledge is not "0.7 of a model".

    Three things to read before the first table.

    1. The cap is part of the score. A row measured at 2048 or 4096 tokens per answer is only comparable inside that band. Anything measured below 2048 is marked floor and ranked in its own table at the bottom, never against a ceiling.
    2. n is the item count, not a formality. HumanEval is out of 164, MMLU-Pro out of 120. A row at a smaller n is plumbing and says so.
    3. build is the llama.cpp that produced the row. Decode rates move 10-20% between builds, so a throughput comparison across different builds is a comparison of builds as much as models.

    What is deliberately missing

    • No composite index. Weighting code, knowledge and speed into one number requires assumptions this project will not make on the reader's behalf.
    • No context-window ranking. Native context is a property of the file, not a measurement; the report covers it per model, including the 1,048,576-token Kimi row and why it is measured at 65536.
    • No per-watt axis yet. Power is measured (§15) but not paired with throughput per model, so any efficiency ranking here would be invented.
